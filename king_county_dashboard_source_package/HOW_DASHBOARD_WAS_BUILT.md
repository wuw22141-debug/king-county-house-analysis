# Complete Guide to Building the King County Dashboard

## 1. Technical Approach

This dashboard is not a collection of static images generated by Python. It consists of two layers:

1. **Python build layer**
   - Fetch data from OpenML;
   - Clean the data and create features with pandas;
   - Train models with scikit-learn;
   - Compute the correlation matrix, model metrics, and feature importance;
   - Convert house records and model results to JSON;
   - Combine the JSON, Plotly.js, and the HTML template into a single HTML file.

2. **Browser interaction layer**
   - HTML provides the page structure;
   - CSS controls layout and visual styling;
   - JavaScript stores the current filter state;
   - JavaScript filters all 21,613 records in the browser;
   - JavaScript recalculates medians, means, grouped statistics, and ZIP-code rankings;
   - Plotly.js uses those statistics to update the interactive charts;
   - The browser can export the currently filtered records to CSV.

Therefore, changing the filters in the sidebar does not require rerunning Python or using a server.

## 8. Feature Engineering

### Time Features

```python
df["sale_year"] = df["date"].dt.year
df["sale_month"] = df["date"].dt.month
df["sale_quarter"] = df["date"].dt.quarter
df["year_month"] = (
    df["date"].dt.to_period("M").astype(str)
)
```

### House Age

```python
df["house_age"] = (
    df["sale_year"] - df["yr_built"]
)
```

### Renovation Indicator

```python
df["renovated"] = (
    df["yr_renovated"] > 0
).astype(int)
```

### Basement Indicator

```python
df["has_basement"] = (
    df["sqft_basement"] > 0
).astype(int)
```

### Price per Square Foot

```python
df["price_per_sqft"] = (
    df["price"] / df["sqft_living"]
)
```

Note: this variable is used only for analysis and must not be used to predict house prices because it directly includes the target variable `price`, which would cause data leakage.

### Construction Decade

```python
df["built_decade"] = (
    df["yr_built"] // 10 * 10
).astype(int)
```

### Space Ratios

```python
df["sqft_per_bedroom"] = (
    df["sqft_living"] /
    df["bedrooms"].replace(0, np.nan)
)

df["bathrooms_per_bedroom"] = (
    df["bathrooms"] /
    df["bedrooms"].replace(0, np.nan)
)

df["living_lot_ratio"] = (
    df["sqft_living"] /
    df["sqft_lot"].replace(0, np.nan)
)
```

## 10. Why Model Results Are Precomputed

Filtered charts can be recalculated instantly in the browser, but retraining a random forest after every filter change is not appropriate for browser-side execution. Therefore:

- The models are trained once during the Python build stage;
- Model metrics, feature importance, actual values, predicted values, and residuals are saved as JSON;
- The dashboard model tab displays fixed test-set results;
- The sidebar filters mainly affect descriptive analysis and the house table.

This is a hybrid architecture: static model results plus dynamic exploratory analysis.

## 17. Browser Statistics Functions

Median:

```javascript
const median = arr => {
  if (!arr.length) return NaN;
  const s = [...arr].sort((a, b) => a - b);
  const m = Math.floor(s.length / 2);

  return s.length % 2
    ? s[m]
    : (s[m - 1] + s[m]) / 2;
};
```

Mean:

```javascript
const mean = arr =>
  arr.length
    ? arr.reduce((a, b) => a + b, 0) / arr.length
    : NaN;
```

Percentile:

```javascript
const percentile = (arr, p) => {
  const s = [...arr].sort((a, b) => a - b);
  const index = (s.length - 1) * p;
  const low = Math.floor(index);
  const high = Math.ceil(index);

  return low === high
    ? s[low]
    : s[low] + (s[high] - s[low]) * (index - low);
};
```

These functions are used for KPIs, automated insights, and grouped charts.

## 19. How Each Chart Is Calculated

### House Price Histogram

Pass the filtered price array directly to:

```javascript
{
  x: filtered.map(d => d.price),
  type: "histogram",
  nbinsx: 55
}
```

### Monthly Trend

First group by `year_month`:

```javascript
const groups = {};

filtered.forEach(d => {
  if (!groups[d.year_month]) {
    groups[d.year_month] = [];
  }
  groups[d.year_month].push(d.price);
});
```

Then calculate:

- Number of records per month;
- Median house price per month.

Use dual Y axes:

- Left axis: sales volume;
- Right axis: median house price.

### Living Area vs. Price Scatter Plot

```javascript
x = sqft_living
y = price
color = grade
```

Use `scattergl` so the points are rendered with WebGL.

### Bedroom and Grade Bar Charts

The browser groups records by category and calculates the median for each group rather than the mean.

### Waterfront Box Plot

Split prices into:

- `waterfront === 0`;
- `waterfront === 1`.

Use Plotly's `box` trace type and hide individual points so numerous luxury-home outliers do not overwhelm the visualization.

### Map

Instead of loading online map tiles, use:

```javascript
x = longitude
y = latitude
color = log10(price)
```

This approach:

- Works fully offline;
- Shows the spatial outline of King County using the house point cloud;
- Does not depend on a map service.

### ZIP-Code Ranking

For each ZIP code, calculate:

- Number of homes;
- Median house price;
- Median price per square foot;
- Median living area.

The ranking includes only ZIP codes with at least 10 records to reduce misleading results from extremely small samples.

### House Quadrant Plot

Use the current filtered sample's:

- Median house price;
- Median living area;

Divide homes into:

- High-price, large homes;
- High-price, small homes;
- Low-price, large homes;
- Low-price, small homes.

### Model Charts

The model tab displays data precomputed in Python:

- MAE bar chart;
- R² color scale;
- Random Forest feature importance;
- Actual vs. predicted values;
- Residual histogram.

## 20. Performance Optimization

Not every scatter plot renders all 21,613 points.

```javascript
const sampleRows = (arr, maxN) => {
  if (arr.length <= maxN) return arr;

  const step = arr.length / maxN;
  const out = [];

  for (let i = 0; i < maxN; i++) {
    out.push(arr[Math.floor(i * step)]);
  }

  return out;
};
```

Sample sizes used:

- Living-area scatter plot: up to about 4,500 points;
- Latitude/longitude map: up to about 6,500 points;
- Quadrant plot: up to about 4,000 points;
- Model actual-vs.-predicted plot: 1,500 points presampled in Python.

Bar charts, KPIs, and statistics still use all filtered records.

## 21. Lazy Rendering by Tab

When the page first opens, it does not redraw every chart at once. It renders only the active tab:

```javascript
function renderActiveTab() {
  if (activeTab === "overview") {
    renderPriceHistogram();
    renderMonthlyTrend();
    renderCorrelation();
  } else if (activeTab === "features") {
    renderAreaScatter();
    renderBedroomBar();
  }
}
```

Benefits:

- Faster initial load;
- Hidden charts do not repeatedly consume browser rendering resources;
- Charts get the correct container dimensions after switching tabs.

## 26. Limitations of the Current Architecture

1. Model results are not retrained when the sidebar filters change;
2. All records are embedded in the HTML, making the file large;
3. There is no true map basemap;
4. The front-end median function sorts the data each time; it would need optimization if the dataset grew to hundreds of thousands of rows;
5. The HTML contains the full dataset, so this architecture is not suitable for sensitive data;
6. Treating `zipcode` as a continuous numeric variable is imperfect; a more rigorous model could encode it categorically;
7. Random Forest feature importance may be biased toward continuous variables or variables with many possible values.

## 28. Most Important Design Decisions

The three most important design decisions in the dashboard are:

1. **Use browser-side filtering instead of running Python for every filter change.**
2. **Embed Plotly.js and JSON in the HTML to enable true single-file offline use.**
3. **Update descriptive charts dynamically while precomputing machine-learning results.**

Together, these decisions make the dashboard:

- Easy to share;
- Deployment-free;
- Highly interactive;
- Still explainable to high school students;
- Capable of demonstrating a complete data-science workflow.
